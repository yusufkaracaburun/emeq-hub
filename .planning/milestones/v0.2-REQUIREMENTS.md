# Requirements: Emeq integration stack (v0.2) — ARCHIVED

**Defined:** 2026-05-14
**Shipped:** 2026-05-17
**Core Value:** Naschool's vrijwillige-bijdrage flow loopt namens School A op School A's eigen Mollie-account via Hub-Connect, met `emeq/mollie-api` SDK + Hub-skeleton + Subscriptions-laag als generieke fundatie voor toekomstige Consumers en providers.

> **Note:** Hub-side substrate voor de Naschool-end-state is volledig geland (Phase 8 D-03 scope-fence). Live E2E door een echte ouder + Naschool-repo wiring (composer-VCS-entries + Stancl-resolver + EnrollmentConfirmed-listener) is gedeferred naar v0.3 als `NSCH-LIVE-E2E`. De Core Value van v0.2 als geshipped is daarmee feitelijk: **"twee fundamenteel verschillende providers productie-gevalideerd via één SDK-pattern, beide via één Hub geconsumeerd, multi-tenant + encrypted-at-rest + audit-logged + admin-managed"**.

## v1 Requirements — outcomes

### Mollie SDK — Validated ✅

- [x] **MOLL-01**: `emeq/mollie-api` skeleton + ServiceProvider + `MollieCredentialResolver`-contract + dual-credential Data-classes
  - **Outcome:** ✅ Validated in Phase 2 (2026-05-14). SDK gepubliceerd als `emeq/mollie-api v0.1.0-alpha.1` op publieke GitHub-repo. 8/8 plans DONE met bonus-deliverables (exception-mappers + idempotency-generator + webhook-helper boven plan-scope). Multi-tenant runtime credential-swap + `MollieApiKeyCredentials`/`MollieOAuthCredentials` met prefix-validatie.

- [x] **MOLL-02**: Mollie Connect OAuth-broker — token-exchange + refresh-flow + encrypted-at-rest
  - **Outcome:** ✅ Validated in Phase 4 (2026-05-14). Provider-agnostisch `OAuthFlow`-contract + `MollieConnectOAuthFlow` + `OAuthFlowRegistry` + `HubMollieCredentialResolver` met lazy-refresh. 5/5 plans, 129/129 tests, BLOCKING acceptance 8/8.

- [x] **MOLL-03**: `emeq/mollie-api` Resources voor Payments + Customers + PaymentMethods + Refunds + Mandates + Subscriptions + PaymentLinks; Idempotency-Key auto-injectie
  - **Outcome:** ✅ Validated in Phase 5a (2026-05-15). 7 resources + 22 routes onder `/v1/mollie/*`. Idempotency-Key auto-forward via hoisted `AbstractMolliePassThroughController::buildClient` op alle 5 write-endpoints (D-06 gap-closure plan 05a-06). 207 tests groen.

- [x] **MOLL-04**: `MollieWebhookVerifier` voor Connect-webhooks — HMAC-SHA256 signature + queueable
  - **Outcome:** ✅ Validated in Phase 5a (2026-05-15). Signature-verify via Mollie SDK helper + anti-spoofing-fetch + fan-out via `spatie/laravel-webhook-server` naar Consumer-callback + stap-0 hard-fail guard bij empty/null `MOLLIE_WEBHOOK_SECRET` (D-08 stap 1).

### Hub-skeleton — Validated ✅

- [x] **HUB-01**: `consumers`/`accounts`/`connections` tabellen + Sanctum-PAT auth + multi-tenant scoping
  - **Outcome:** ✅ Validated in Phase 3 (2026-05-14). 5/5 plans, 28 tests groen incl. encryption-at-rest voor alle 4 credential-velden en cross-Consumer query-isolation. Acceptance via `hub:consumer:create` + `GET /v1/ping`.

- [x] **HUB-02**: Provider-agnostisch `OAuthFlow`-contract met `MollieConnectOAuthFlow` als eerste implementatie
  - **Outcome:** ✅ Validated in Phase 4 (2026-05-14). 5/5 plans, 129/129 tests groen, BLOCKING acceptance 8/8. `FakeOAuthFlow` bewijst pattern-portability (SC-4) — niet Mollie-specifiek.

- [x] **HUB-03**: Pass-through REST API `/v1/mollie/*` met Bearer→Consumer→Account→Connection-resolutie + audit + OpenAPI
  - **Outcome:** ✅ Validated in Phase 5a (2026-05-15). Multi-tenant resolutie + `pass_through_calls` audit-log + error-mapping (401→502 cloaked, 422→422, 404→404, 429→429+RetryAfter, 5xx→502, timeout→504) + Scramble OpenAPI op `/docs/api`. Cross-Consumer-access → 404 (geen leakage).

- [x] **HUB-04**: Filament v4 admin-paneel op `/admin` met 7 resources + Spatie-roles + no-secret-leak
  - **Outcome:** ✅ Validated in Phase 9 (2026-05-16) + Phase 10 polish (2026-05-16). 11/11 + 6/6 plans, HUB-04 SC-1..SC-10 bewezen via 52 nieuwe tests in `tests/Feature/Admin/` (15 test-classes) + 1 audit-migratie + 11 deferred review-findings closed. Spatie laravel-permission ^6 + 2-rol-model (`super-admin`/`staff`) + 6 permissions (drop `is_emeq_staff` boolean per D-05). `ProviderCredentialDescriptor` (D-04) als single source of truth. ADR `filament-admin-panel.md`. 437 tests / 1479 assertions / 1 pre-existing incomplete.

- [x] **HUB-05**: Pass-through REST API `/v1/snelstart/{path}` + `HubSnelstartCredentialResolver` + audit in eigen `pass_through_calls`
  - **Outcome:** ✅ Validated in Phase 5b (2026-05-16; verifier-pass 2026-05-17). 5/5 plans + `05b-VERIFICATION.md` passed 8/8 must-haves. SC-1..SC-8 bewezen via 86 Phase-5b-scoped tests (15 testfiles). CR-01 (415-guard) + CR-02 (PII-safe `query_keys`) + CR-03 (NULL fingerprint empty body) code-resident. UAT 9/9 live-passed. SECURITY 24/24 gemitigeerd. ADR `pass-through-calls-table.md` (afgesplitst van `webhook_calls`).

- [x] **HUB-06**: Snelstart webhook-handler op `POST /webhooks/snelstart` met HMAC + Connection-resolutie via `administratieId` + async fan-out
  - **Outcome:** ✅ Validated in Phase 5c (2026-05-17). 5/5 plans + HUB-06 SC-1..SC-5 bewezen via 5 end-to-end-tests in `tests/Feature/SnelstartWebhookEndToEndTest.php` + per-scenario coverage in plans 02/03/04. HMAC-verifier + middleware verplaatst naar `emeq/snelstart-api` SDK (`SnelstartWebhookSignature` + `VerifySnelstartSignature`) per ADR `sdk-redistributability-boundary.md`. ADR `snelstart-webhook-ingress.md` (gitignored lokaal artifact). **Productie-cert:** Hub-side compleet; live cert wacht op Snelstart-partner-respons (Gmail draft `r-8836998535038336548` ≤2026-05-26).
