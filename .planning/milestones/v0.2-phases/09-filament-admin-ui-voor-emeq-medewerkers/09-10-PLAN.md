## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-10-01 | Elevation of Privilege | Staff-rol User upgrade zichzelf naar super-admin | mitigate | `canAccess()` + `shouldRegisterNavigation()` beide gated op `manage-staff`-gate die `hasRole('super-admin')` checkt. PermissionGatingTest Test 1+3 bewijzen dat staff geen toegang heeft. |
| T-09-10-02 | Spoofing | Filament v4 caches navigation-state; staff zou theoretisch een gecachte super-admin-nav kunnen zien na role-downgrade | accept | Filament v4 renders navigation per-request (Livewire-component). Geen permanente cache. Bij role-flip: volgende `/admin`-request herrendert. Toekomstige tightening: explicit `Cache::flush(...)` bij role-change (backlog). |
| T-09-10-03 | Information Disclosure | Password-hash zichtbaar in HTML of API | mitigate | User-model heeft `#[Hidden(['password', 'remember_token'])]` — Eloquent `toArray()` redacts. Form-`password`-veld is `->password()` (input-type password). Geen renderpath voor hash. |
| T-09-10-04 | Tampering | Form bypassing `unique` constraint via concurrent submits | accept | Postgres-level UNIQUE constraint op `users.email` (Laravel-default). Race-condition vangt DB-laag op. |
| T-09-10-05 | Tampering | `syncRoles([$role])` wist alle bestaande rollen | accept | Per ontwerp (D-05): één rol per User (super-admin OF staff). `syncRoles` is correct semantic. `assignRole` zou stacken — niet gewenst voor binary role-model. |
| T-09-10-06 | Repudiation | Wie maakte/wijzigde welke User → geen audit-trail | accept | Out of scope per CONTEXT.md (HUB-AUDIT backlog). Documenteren in plan 09-11. |
| T-09-10-SC | Tampering | Geen package-install | accept | Plan 09-10 wijzigt alleen Resource + Provider + tests. |
</threat_model>
