Huidige Consumer-model interface:
```php
namespace App\Models;

#[Fillable(['name', 'slug', 'webhook_callback_url', 'webhook_callback_secret'])]
class Consumer extends Authenticatable
{
    use HasApiTokens, HasFactory;

    // protected casts() returns ['webhook_callback_secret' => 'encrypted']
    public function accounts(): HasMany;
}
```

Cashier-Mollie's `Laravel\Cashier\Billable`-trait verwacht:
- Een numerieke primary-key (Consumer heeft `$table->id()` → OK)
- Eloquent-model met `HasFactory` (Consumer heeft 'm → OK)
- Een polymorfe `morphMany`-relatie naar `Subscription` via `owner_id` + `owner_type` op `subscriptions`-tabel (Cashier ships dit; Billable-trait registreert 'm automatisch)

Cashier-Mollie's `cashier.user_model` config-key:
- Wordt gelezen door verschillende Cashier-internals voor model-resolution (bv. webhook-controllers gebruiken het om de Billable terug-te-vinden via `owner_type`).
- Default in Cashier-Mollie's gepubliceerde `config/cashier.php` is `App\Models\User` (of `App\User` op pre-9.x apps). Wij overschrijven naar `App\Models\Consumer`.

Bestaande Hub-test-pattern (uit StubsMollieClient + bestaande Mollie-tests):
- `Consumer::factory()->create()` levert een Consumer met `name` + `slug` (autogen).
- Geen email-kolom (Cashier-Mollie sommige features verwachten `extra_billing_information` of `email` op de Billable — Cashier-Mollie's `Customer::firstOrCreateMollieCustomer()` leest `email`/`name` als zachte hint, maar kan zonder). Voor v0.2: geen email-kolom toevoegen aan Consumer; PlanResolver in 06-04 + create-subscription in 06-05 verifieert dat Cashier zonder email werkt of we voegen 'm dan toe (NIET in dit plan — chirurgisch).

Cashier-migration-defaults (de gepubliceerde `*_create_subscriptions_table.php` uit Cashier-Mollie ^2.20):
```php
Schema::create('subscriptions', function (Blueprint $table) {
    $table->id();
    $table->morphs('owner');          // owner_id + owner_type
    $table->string('name')->index();
    $table->string('plan');
    // ... mollie_subscription_id, status, trial_ends_at, ends_at, etc.
});
```

Cashier's `$table->morphs('owner')` levert `owner_id` (unsigned bigInteger) + `owner_type` (string, max 255). Het `owner_type` is een Eloquent-class-FQN. Default zal Cashier-Mollie bij creates `App\Models\User::class` ofwel `\Auth::guard()->getProvider()->getModel()` schrijven — afhankelijk van Cashier-Mollie's `cashier.user_model` config-key. **Daarom moeten we die config-key zetten vóór we eerste subscription-create doen.**

Bestaande migration-conventie:
- Forward-only `up()`; bestaande migrations hebben wél `down()` voor lokale dev-reset (zie `2026_05_14_000001_create_consumers_table.php` regel 22-25).
- Timestamp-prefix `YYYY_MM_DD_NNNNNN_` — dit plan timestamps na de gepubliceerde Cashier-migrations (die op `2026_05_16_*` of `2026_05_17_*` zullen landen afhankelijk van wanneer plan 06-02 ran). Gebruik `2026_05_17_000001_` om zeker na alle Cashier-publish-timestamps te komen.

Test-conventie (zie `tests/Feature/Api/V1/Mollie/CustomersTest.php`):
- `use Illuminate\Foundation\Testing\RefreshDatabase;` op de class.
- Eén test per gedragslijn; descriptive method-names (`test_<scenario>_<expected_outcome>`).
- Database stubs via factories; Mollie-API-calls via `StubsMollieClient` trait.
