Phase 5a stap-0 pattern (uit `app/Http/Controllers/Webhooks/MollieWebhookController.php` regel 37-46):
```php
$secret = config('services.mollie.webhook_secret');
if (! is_string($secret) || $secret === '') {
    $this->auditFailedWebhook($request, 'webhook_secret_not_configured');
    return response()->json(['error' => 'webhook_misconfigured'], 500);
}
```

Wij hergebruiken DIT pattern verbatim, maar in een **middleware** in plaats van inline-in-controller — zodat Cashier-Mollie's eigen `WebhookController` z'n logica niet hoeft te kennen.

Cashier-Mollie published webhook-routes (uit WebFetch op `routes/webhooks.php` in 06-02-prep):
- `POST {webhook_url}` → `Laravel\Cashier\Http\Controllers\WebhookController@handleWebhook`
- `POST {first_payment_webhook_url}` → `Laravel\Cashier\Http\Controllers\FirstPaymentWebhookController@handleWebhook`
- `POST {aftercare_webhook_url}` → `Laravel\Cashier\Http\Controllers\AftercareWebhookController@handleWebhook`

`Cashier::$registersRoutes = true` by default, dus Cashier registreert deze routes automatisch tenzij wij opt-out.

**Strategie:** opt-out van Cashier's automatic route-registration, dan handmatig 1 catch-all route op `cashier/webhook` registeren die ook first_payment/aftercare opvangt via Cashier's eigen controllers, ALLES achter onze guard-middleware.

ALTERNATIEF — eenvoudiger: laat Cashier z'n routes registreren ZOALS HET WIL (`webhooks/mollie`, `webhooks/mollie/first-payment`, `webhooks/mollie/aftercare`), maar voeg een **globale middleware-group** toe via `bootstrap/app.php` die ALLEEN op die 3 paden de guard runt. Dit is fragieler want we koppelen aan vendor's webhook-URL-conventie.

**Beste pad voor dit plan:**
1. Set `Cashier::ignoreRoutes()` in een ServiceProvider boot — dit voorkomt dat Cashier z'n eigen routes registreert.
2. Plak ZELF 3 routes op explicit paden `cashier/webhook`, `cashier/webhook/first-payment`, `cashier/webhook/aftercare`, ELK achter onze guard-middleware, doorvoorgaande naar Cashier's eigen controllers (`Laravel\Cashier\Http\Controllers\WebhookController` etc.).
3. Update `config/cashier.php`'s `webhook_url`-key naar `cashier/webhook` zodat Cashier's eigen URL-generators (used in subscription-create om de subscription's `webhookUrl` te zetten) onze paden gebruiken.

Cashier's `Cashier::ignoreRoutes()` is statiek op `Laravel\Cashier\Cashier`-class. Roep aan in `AppServiceProvider::boot()`:
```php
\Laravel\Cashier\Cashier::ignoreRoutes();
```

Bestaande webhook-route-pattern (uit `routes/webhooks.php`):
```php
Route::post('/webhooks/mollie/{connection_id}', MollieWebhookController::class)
    ->where('connection_id', '[0-9]+')
    ->name('webhooks.mollie');
```

Voor Cashier — we MOETEN een wrapper-controller maken die parent's `handleWebhook` aanroept maar tegelijk in `webhook_calls` audit'd. Cashier's eigen `WebhookController::handleWebhook(Request)`-signature is publiek (lees `vendor/mollie/laravel-cashier-mollie/src/Http/Controllers/WebhookController.php` na 06-02-install).

OF — eenvoudiger nog — we routen direct naar Cashier's controller maar wrap'en de middleware-laag eromheen:
```php
Route::post('/cashier/webhook',
    [\Laravel\Cashier\Http\Controllers\WebhookController::class, 'handleWebhook']
)
->middleware('cashier.webhook.secret')
->name('webhooks.cashier.default');
```

Met deze aanpak hoeven we GEEN eigen wrapper-controller te maken (de audit-write zou dan inline in de middleware kunnen — middleware kan na `$next($request)` callen om de response-status te audit'en).

**Gekozen pad voor dit plan:** geen eigen wrapper-controller; alleen de guard-middleware doet de audit-write (pre- + post-response). Plan 06-06 levert dus uiteindelijk:
- 1 nieuwe middleware (`RequireCashierWebhookSecret`) die hard-fail-guard + audit doet
- 0 nieuwe controllers (Cashier's eigen WebhookController etc. blijven het werk doen)
- 3 nieuwe routes voor de Cashier-webhook-endpoints (default + first-payment + aftercare)
- 1 service-provider boot-call (`Cashier::ignoreRoutes()`)
- 1 config-edit (`config/cashier.php` webhook_url naar `cashier/webhook`)

LET OP de bestaande Phase 5a `MollieWebhookController` test (`MollieWebhookSignatureTest.php`) checkt dat een lege secret tot 500 leidt; wij replicheren die assertion-stijl in `CashierWebhookSecretGuardTest`.

Bestaande Spatie `WebhookCall`-tabel velden (uit `MollieWebhookController::auditFailedWebhook`):
- `name` (string) — `'cashier'` voor onze rijen (`'mollie'` blijft voor Phase 5a Connect-rijen)
- `url`, `headers`, `payload`, `exception` velden

**Belangrijke gotcha:** `RequireCashierWebhookSecret` checkt `config('services.cashier.webhook_secret')` — die binding hebben we al in plan 06-02 toegevoegd aan `config/services.php`. Verifieer dat het in 06-02-SUMMARY staat; zo niet, voeg het hier toe als follow-up.

    **Stap A — Middleware:**

    Maak `app/Http/Middleware/RequireCashierWebhookSecret.php`:
    ```php
    <?php

    declare(strict_types=1);

    namespace App\Http\Middleware;

    use Closure;
    use Illuminate\Http\Request;
    use Spatie\WebhookClient\Models\WebhookCall;
    use Symfony\Component\HttpFoundation\Response;

    /**
     * D-11: stap-0 hard-fail guard voor /cashier/webhook-routes.
     * Analoog aan Phase 5a's `MollieWebhookController`-regel 37-46.
     *
     * Reden voor middleware-vorm (i.p.v. inline-in-controller): Cashier's
     * eigen `Laravel\Cashier\Http\Controllers\WebhookController` is een
     * vendor-class die wij niet patchen; een middleware wrapt 'm wel.
     *
     * NIET een signature-verify: reguliere Mollie-webhooks (NIET Connect)
     * zijn UNSIGNED en gebruiken een obscured URL als auth. Onze
     * `CASHIER_WEBHOOK_SECRET` is dus een aanvullende laag bovenop
     * Mollie's eigen URL-obscurity, niet een HMAC-key.
     */
    final class RequireCashierWebhookSecret
    {
        public function handle(Request $request, Closure $next): Response
        {
            $secret = config('services.cashier.webhook_secret');

            if (! is_string($secret) || $secret === '') {
                $this->auditFailedWebhook($request, 'webhook_secret_not_configured');

                return response()->json([
                    'error' => 'webhook_misconfigured',
                ], 500);
            }

            return $next($request);
        }

        private function auditFailedWebhook(Request $request, string $exception): void
        {
            WebhookCall::create([
                'name' => 'cashier',
                'url' => $request->fullUrl(),
                'headers' => $request->headers->all(),
                'payload' => $request->json()->all() ?: ['_raw' => substr($request->getContent(), 0, 1000)],
                'exception' => $exception,
            ]);
        }
    }
    ```
