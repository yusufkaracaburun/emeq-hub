Cashier-Mollie ^2.20 published artifacts (geverifieerd via WebFetch op `main`-branch):

Publish-tags:
- `cashier-migrations` → `database/migrations/` (10 migration .php.stub bestanden, worden door publish met timestamp-prefix uitgepakt)
- `cashier-configs` → `config/cashier.php` + `config/cashier_plans.php` + `config/cashier_coupons.php`
- `cashier-views` → resources/views (NIET in scope — Cashier-Mollie ships invoice-templates die we niet gebruiken in v0.2)
- `cashier-translations` → lang/ (NIET in scope)

Service-provider auto-discovery: `Laravel\Cashier\CashierServiceProvider` zit in `extra.laravel.providers` van het package — wordt automatisch geregistreerd door Laravel's package-discovery (geen handmatige `bootstrap/providers.php`-edit nodig).

Config-shape (`config/cashier.php` na publish):
```
return [
    'webhook_url' => 'webhooks/mollie',          // Cashier-default; we hernoemen NIET (plan 06-06 bouwt erop)
    'aftercare_webhook_url' => '...',
    'locale' => 'en_US',
    'first_payment' => [
        'webhook_url' => 'webhooks/mollie/first-payment',
        'method' => null,
        'redirect_url' => config('app.url'),
        'amount' => ['value' => '0.01', 'currency' => 'EUR'],
        'description' => config('app.name'),
    ],
    // ... order_number_generator, update_payment_method
];
```

Config-shape (`config/cashier_plans.php` na publish): defaults + plans-array; we laten 'plans' leeg in dit plan en vullen 'm via `billing-plans.php` + `PlanResolver` in plan 06-04 (D-05 / D-06).

Migration-set (10 tabellen na publish):
- `subscriptions`, `subscription_items`
- `orders`, `order_items`
- `payments` (LET OP: collision-risico met Hub's bestaande tabellen — er bestaat al géén `payments`-tabel in Hub vandaag, dus geen botsing; verify via `php artisan migrate --pretend` of `ls database/migrations` vóór `migrate`)
- `refunds`, `refund_items`
- `credits`
- `applied_coupons`, `redeemed_coupons`

Belangrijke env-vars die Cashier-Mollie verwacht:
- `CASHIER_MOLLIE_KEY` — Emeq's eigen Mollie test-API-key (`test_…`-prefix). Cashier-Mollie leest deze via `config('mollie.key')` of `config('cashier.mollie.key')` — de `mollie/laravel-mollie` package-config leest 'm uit `MOLLIE_KEY` env var. We aliassen `CASHIER_MOLLIE_KEY` in `.env.example` voor duidelijkheid, maar de daadwerkelijke env-key die `mollie/laravel-mollie` leest is `MOLLIE_KEY`. **Plan 06-02 zet beide env-vars in `.env.example` en documenteert in een NL-comment dat ze identiek moeten zijn.**

Voor `config/services.php` voegen we een `cashier`-block toe (analoog aan `services.mollie.webhook_secret` uit Phase 5a):
```php
'cashier' => [
    'webhook_secret' => env('CASHIER_WEBHOOK_SECRET'),
],
```

Dit is GEEN onderdeel van Cashier-Mollie's eigen config — Cashier-Mollie heeft géén ingebouwde HMAC-signature-verify (Mollie's gewone webhooks zijn UNSIGNED en gebruiken obscured URLs als auth). De `CASHIER_WEBHOOK_SECRET` is voor onze eigen hard-fail guard die in plan 06-06 een wrapper-controller om Cashier's `WebhookController` heen plakt (D-10/D-11 — zelfde reasoning als Phase 5a stap-0 guard). Mollie-Connect-webhooks zijn WEL signed; reguliere Mollie-webhooks niet — daarom voegen we onze eigen secret-laag toe.

Bestaande Hub-conventies om te matchen:
- `config/mollie.php` heeft `declare(strict_types=1);` — Cashier's gepubliceerde configs gebruiken geen `declare`. Niet aanpassen — Cashier-vendor-files matchen niet onze conventie en we mogen die niet patchen.
- `composer.json` heeft `"sort-packages": true` — composer schrijft het automatisch correct gesorteerd.
- `composer.json` `"minimum-stability": "dev"` + `"prefer-stable": true` — Cashier-Mollie v2.20.1 is `stable`, dus geen problemen.
- `composer.json` heeft een `"audit"` block met ignored advisories (Snelstart Saloon v3 issues uit STATE.md). Niet aanraken.
