<objective>
Lever de service-laag: `AccountSubscriptionManager` als single-entry-point voor alle Mollie Subscription-flows + Hub-state-machine-transitions. Voeg ook de status-cast op het model toe (Wave 2 — enum bestaat nu uit plan 07-02). Geen controllers (komen in plan 07-04), geen webhook-routing (komt in plan 07-05).

Manager-API (D-13):
- `create(Account $account, Connection $connection, CreateAccountSubscriptionDto $dto): AccountSubscription` — persist `pending` → Mollie `subscriptions->createForId($mollie_customer_id, [...])` → `pending → active` + `mollie_subscription_id` gevuld
- `cancel(AccountSubscription $sub): void` — Mollie `subscriptions->cancelForId($customerId, $subscriptionId)` → `* → canceled`
- `pause(AccountSubscription $sub, string $reason): void` — Hub-only: `active → paused` (zonder Mollie-call)
- `resume(AccountSubscription $sub): void` — Hub-only: `paused → active`
- `syncFromMollie(AccountSubscription $sub): void` — GET subscription via SDK; bij Mollie-`NotFoundException` → state `Unknown` (D-17)
- `recordPaymentEvent(AccountSubscription $sub, array $paymentPayload): void` — inspecteert `status` + `details.failureReason`; mandate_invalid → `active → paused` (D-16); paid → update `last_payment_status='paid'` + `last_webhook_event_at`

Idempotency-Key forward (D-14): manager's `create` accepteert een optionele 4e parameter `?string $idempotencyKey = null` die als header op de Mollie-client wordt gezet via `MollieApiClient::setIdempotencyKey()` (analog: `AbstractMolliePassThroughController::buildClient` regels 196-206).

Purpose: Plan 07-04's controllers wrappen deze manager-calls met Form-Request-validatie + HTTP-vertaling. Plan 07-05's webhook-handlers roepen `syncFromMollie` + `recordPaymentEvent` aan.

Output:
- 1 DTO + 1 service class
- 1 mutatie op `AccountSubscription`-model (status-cast toevoegen)
- 3 unit-tests (create / sync / recordPaymentEvent)
</objective>
