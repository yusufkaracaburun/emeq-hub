<objective>
Bouw twee read-only Filament Resources: `AccountResource` (overzicht van Accounts per Consumer met filter + count-kolom) en `WebhookCallResource` (audit-log-viewer voor Spatie webhook_calls met de 4 nieuwe kolommen uit plan 09-01). Beide Resources zijn ListPage + ViewPage; geen Create/Edit/Delete. Geen mutate-actions.

Twee Resources in één plan omdat beide:
- Read-only (laag risico)
- Geen file-overlap (eigen Resource-class + eigen Page-classes)
- Combined context-footprint blijft <50% (samen ~3 tabel-definities + 2 simpele tests)

Purpose: AccountResource = overzicht-tool voor Emeq-staff (welke schools heeft Consumer X?). WebhookCallResource = debugging-tool voor incoming/outgoing webhook-flows (Mollie + Snelstart + Cashier). De 4 audit-kolommen van plan 09-01 (`direction`/`provider`/`consumer_id`/`status`) maken filterbaar wat Spatie's default-schema niet kon.

Output:
- 2 Resource-classes + 4 Page-classes (2 List + 2 View)
- 2 nieuwe feature-tests
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Filament read-render → browser-HTML | Account-model heeft geen encrypted fields (alle velden zijn safe-render: consumer_id, external_id, display_name). |
| WebhookCallResource → Spatie webhook_calls (potentially sensitive payloads) | Spatie webhook_calls.payload kan partner-webhook-payload bevatten met semi-sensitive data (Mollie payment-id's, customer-id's). Geen secrets (Mollie-id's zijn opaque per Phase 7-01 D-02), maar wel info-disclosure-risk als payload onverhoopt PII bevat. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-07-01 | Information Disclosure | Spatie webhook_calls.payload toont sensitive PII (klantnamen, e-mails) | accept | Mollie + Snelstart-webhook-payloads bevatten primair partner-id's (`tr_xxx`, `cst_xxx`); klant-PII zit in API-fetches NIET in webhook-payloads (Phase 5a-pattern). Plan 09-11 ADR documenteert: als Naschool-uitbreiding (Phase 8) ooit consumer-PII via webhook stuurt, herziening van deze acceptatie. |
| T-09-07-02 | Elevation of Privilege | Read-only Resource laat Account/WebhookCall muteren via Livewire-action-injection | mitigate | Resource heeft alleen `index` + `view` in `getPages()`. Geen `Action::make()` met `->action(fn)` die muteert. Filament v4 blokkeert Livewire-mutaties op niet-geregistreerde actions. |
| T-09-07-03 | Information Disclosure | Cross-Consumer admin-view (staff-A ziet alle Consumers' Accounts) | accept | Per ontwerp (CONTEXT.md): Emeq-staff is Hub-level admin, niet tenant-scoped. Documenteren in plan 09-11. |
| T-09-07-04 | Tampering | Account.external_id wijzigen via UI | mitigate | AccountResource heeft geen Edit-page. Mutaties gebeuren via Hub `/v1/accounts`-API (Phase 5b) of Account-factory in dev. |
| T-09-07-SC | Tampering | Geen package-install | accept | Plan 09-07 wijzigt alleen Resource-files + tests. |
</threat_model>
