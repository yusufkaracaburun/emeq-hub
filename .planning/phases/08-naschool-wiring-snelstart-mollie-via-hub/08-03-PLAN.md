<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → Filament-action | Authenticated Filament-staff (Spatie permission gate) crossen hier |
| Action-callback → Connection::create | Pre-validated Filament-form-data + Account-record cross hier |
| Action-callback → OAuthFlowRegistry | Phase-4 contract — provider-validation happens in registry |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-03-01 | Elevation of Privilege | Cross-Consumer Connection-creation | mitigate | Filament's record-action bindt aan `Account $record` van de calling Resource; AccountResource list is per-design Phase-9 scoped op staff-view (geen Consumer-scoping nog — staff zien alle Accounts). Action zelf doet `$account->connections()->create(...)` zodat FK enforced is. Testen: `actingAs($staffWithoutManageConnections)` → action niet zichtbaar. Geen mass-assign van `account_id` vanuit form |
| T-08-03-02 | Tampering | OAuth state-parameter forgery | mitigate | `Str::random(48)` = 48-char URL-safe random (Phase 4 pattern). State opgeslagen in Connection.oauth_state met 30-min TTL. CallbackController verifieert via Phase-4 InitController-test-paden (al gevalideerd). Geen test-coverage in deze plan vereist — bestaande Phase 4 `CallbackControllerTest` dekt het |
| T-08-03-03 | Information Disclosure | Authorize-URL leak via Notification | accept | Authorize-URL bevat `client_id` (publiek) + `state` (per-flow random) + `redirect_uri` (publiek). Geen credentials in URL. Livewire `redirect()->away()` is direct — geen Notification-message met URL |
| T-08-03-04 | Denial of Service | Spam pending Connections (geen rate-limit) | accept | Filament-action staat alleen open voor authenticated staff met `manage-connections`. Pending Connections worden door `oauth:prune-pending` artisan-command (Phase 4-05) opgeruimd. Geen rate-limit nodig op v0.2 admin-tool |
| T-08-03-05 | Spoofing | Onbekende provider in form-submit | mitigate | `Radio::make('provider')->options(self::oauthCapableProviders())` levert alleen valid keys. `OAuthFlowRegistry::for($provider)` gooit InvalidArgumentException als provider unknown — gevangen + Notification 'Geen OAuth-flow beschikbaar' (UI-SPEC regel 172) |
</threat_model>
