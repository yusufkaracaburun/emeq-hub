<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI → service | Operator-input (Emeq-staff) crosst hier; geen ongeauthenticeerde caller |
| Filament-wizard → service (downstream, PLAN 08-02) | Pre-authenticated Filament-staff (Spatie `manage-consumers`) crosst hier |
| Service → DB | Encrypted-cast invariant geldt op model-laag; service mag plain values doorzetten |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-01-01 | Information Disclosure | `webhook_callback_secret` retour-shape | mitigate | Service returnt plain `webhook_callback_secret` alleen in return-value; nooit loggen, nooit persistent dump. Eloquent `encrypted` cast op `Consumer::$casts` (regel 23-28) garandeert at-rest-encryption automatisch. Test: `assertDatabaseMissing('consumers', ['webhook_callback_secret' => $plainSecret])` |
| T-08-01-02 | Information Disclosure | Plain PAT-token in return-value | mitigate | Service returnt `plain_token` alleen voor eenmalige Cache-flash (PLAN 08-02). Bestaand Phase-3 pattern: `HubConsumerCreate` toont al via `$this->warn()` — geen wijziging in CLI-pad. Test: `assertDatabaseMissing('personal_access_tokens', ['token' => $plainToken])` (Sanctum bewaart alleen sha256-hash) |
| T-08-01-03 | Tampering | Partial-create-rollback bij failure | mitigate | `DB::transaction(fn () => ...)`-closure gooit alle gemaakte rows weg bij willekeurige exception. Test: forceer `Connection::create` failure (FK-violation), assert `Consumer::count() === 0` + `Account::count() === 0` |
| T-08-01-04 | Repudiation | Wie heeft welke Consumer aangemaakt | accept | `HUB-AUDIT` backlog item dekt audit-trail via `spatie/laravel-activitylog` later. Voor v0.2 niet vereist; CLI-output + Filament-notification volstaan |
| T-08-01-05 | Denial of Service | Onbegrensd grote `abilities`-array | mitigate | `TokenAbilities::all()`-whitelist enforcen — onbekende abilities → throw `InvalidArgumentException` met NL-message (zelfde shape als CLI `--abilities` validatie regel 32-39) |
</threat_model>
