Request-shape voor elke Hub-pass-through-call vanuit Naschool:

```http
POST https://hub.emeq.test:8090/v1/mollie/payments        (of /v1/snelstart/Verkoopfacturen)
Authorization: Bearer {EMEQ_HUB_PAT}                       ← Sanctum-PAT van naschool-Consumer
Content-Type: application/json
Accept: application/json
X-Account-Id: {account_id_uit_resolver}                    ← uuid van de Account-rij in de Hub

{...partner-payload...}
```

Resolution-keten in de Hub:
1. Sanctum verifieert Bearer-PAT → resolveert Consumer (= naschool)
2. ResolveMollieAccount / ResolveSnelstartAccount middleware leest X-Account-Id, looked up tegen `accounts.id WHERE consumer_id = naschool.id`
3. Middleware laadt actieve Connection voor (Account, provider); 404 als geen Connection
4. Pass-through-controller doet partner-call met Connection.access_token (Mollie) of client_key+subscription_key (Snelstart)

Naschool's resolver moet dus per Stancl-tenant de juiste UUID retourneren — een mapping `tenant-id → hub-account-id`. **Opslag-route LOCKED (zie `<note>`):** Stancl `data`-jsonb-column, key `emeq_hub_account_id`. Resolver leest `tenancy()->tenant->data['emeq_hub_account_id']` (of de Stancl-equivalente jsonb-accessor zoals het Tenant-model die exposeert). GEEN dedicated migration / explicit column.
</interfaces>
