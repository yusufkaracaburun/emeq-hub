From app/OAuth/Contracts/OAuthFlow.php (Plan 04-01 output):
```php
interface OAuthFlow {
    public function getAuthorizationUrl(Account $account, array $scopes, string $state): string;
    public function exchangeCode(Connection $connection, string $code): Connection;
    public function refreshToken(Connection $connection): Connection;
    public function revoke(Connection $connection): void;
}
```

From Mollie OAuth2 docs (https://docs.mollie.com/reference/oauth2/tokens):
- Token-endpoint: POST https://api.mollie.com/oauth2/tokens
- Authorize-endpoint: https://my.mollie.com/oauth2/authorize (browser-facing, GET)
- Token-exchange: form-encoded body met grant_type=authorization_code, code, redirect_uri, client_id, client_secret
- Refresh: form-encoded body met grant_type=refresh_token, refresh_token, client_id, client_secret
- Revoke: DELETE /oauth2/tokens met Basic-auth client_id:client_secret + token_type_hint + token
- Response shape: {access_token, refresh_token, expires_in (seconds), scope, token_type}

From Laravel Http facade (Illuminate\Support\Facades\Http):
- `Http::asForm()->post($url, $array)` → form-encoded
- `Http::withBasicAuth($user, $pass)->delete($url, $body)` → DELETE with Basic auth
- `Http::fake([url-pattern => Http::response([...])])` for tests
- `->throw()` raises RequestException on non-2xx
- `->json()` returns array
</interfaces>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Hub → Mollie OAuth-endpoint | HTTPS-only; client_secret in body; tokens in response — `Http::throw()` faalt loud bij non-2xx |
| Cache::lock → Redis | Lock per connection_id voorkomt race-condition op token-refresh |
| config/services.php → env-vars | Secrets in env-vars (niet hard-coded); `env()` alleen in config-files (Laravel config-cache rule) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-02-01 | Information Disclosure | exchangeCode/refreshToken | mitigate | `Http::throw()` lekt geen tokens; geen `Log::info($response->body())`; in eventuele custom-exception alleen `$response->status()` + correlatie-ID, geen body. PATTERNS.md regel 1561-1564. |
| T-04-02-02 | Information Disclosure | Tokens in DB | mitigate | Bestaande `'encrypted'` cast op `access_token`/`refresh_token` (Phase 3 ConnectionEncryptionTest bewees at-rest); Plan 04-01 raakt deze niet. |
| T-04-02-03 | Tampering | Authorization-code interception (RFC 6749 §10.5) | mitigate | HTTPS-only redirect_uri (production-env enforce). Geen mitigation in code — invariant uit `.ai/rules/global.md`. |
| T-04-02-04 | DoS | Race-condition op refresh (parallelle requests) | mitigate | D-05 `Cache::lock("oauth:refresh:{$connectionId}", 30)->block(15, …)`. Tweede request wacht max 15s, leest dan vernieuwde token. |
| T-04-02-05 | Information Disclosure | Open-redirect via callback | accept | Phase 4 callback returnt JSON, géén HTTP-redirect naar Consumer-supplied URL (D-08). Out-of-scope; documenteren voor wanneer dat verandert. |
| T-04-02-06 | Spoofing | client_secret leak in error-output | mitigate | Pint code-formatting + `.ai/rules/global.md` invariant ("nooit secrets in logs"). `Http::throw()`-exception bevat URL + status, niet body. |
</threat_model>
